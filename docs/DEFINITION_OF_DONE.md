# Definition of Done (DoD) - TLiFlashManager

모든 기능 및 코드 변경사항은 아래 9단계의 검증 게이트(Gate)를 100% 만족해야 "완료(Complete/Release)"로 간주한다.

---

## 1. Requirements & Domain Integrity (요구사항 및 도메인 완결성)
- [ ] 반도체 엔지니어가 요구한 플래시 메모리 맵 조작 및 바이너리/코드 생성 기능이 누락 없이 전부 구현되었는가?
- [ ] ARM Cortex-M0 벡터 테이블(0x0000_0000/Remap) 및 NOR Flash 물리 제약(4KB Sector, 64KB Block 정렬)이 준수되었는가?
- [ ] 예외 케이스(주소 충돌, 용량 초과, 0바이트 세그먼트, 비정렬 주소)가 정의되고 처리되었는가?

## 2. Code Quality & Modularity (코드 품질 및 모듈성)
- [ ] UI 컴포넌트, 도메인 검증기, 바이너리 파서, 코드 제너레이터 간의 모듈 경계가 명확한가?
- [ ] 중복 코드(DRY 원칙)를 방지하고 공통 메모리 연산 유틸리티를 재사용했는가?
- [ ] 불필요한 무거운 서드파티 라이브러리를 추가하지 않았는가?
- [ ] TypeScript Strict Mode 오류 (`tsc --noEmit`)가 0건인가?
- [ ] 콘솔 로그나 디버깅용 코드가 정리되었는가?

## 3. Production Build & Lint (빌드 및 정적 분석)
- [ ] `npm run build` 프로덕션 빌드가 에러 없이 성공하는가?
- [ ] 순환 참조(Circular Dependency) 및 번들링 에러가 0건인가?

## 4. Binary & Math Integrity QA (바이너리 및 수치 무결성)
- [ ] 주소 계산에서 1바이트 오차(Off-by-one)가 없는가?
- [ ] 생성된 C 헤더(`tcon_flash_map.h`)와 린커 스크립트(`.ld`, `.sct`)의 매크로/영역 주소가 메모리 맵과 100% 일치하는가?
- [ ] 바이너리 패킹 시 0xFF 빈 공간 패딩 및 오프셋 정렬이 정확한가?
- [ ] CRC16/CRC32/Checksum 연산이 표준 알고리즘 테스트 벡터와 일치하는가?

## 5. Functional QA (기능 무결성 검증)
- [ ] 세그먼트 생성, 수정, 삭제, 주소 변경 시 실시간 반영이 정상인가?
- [ ] 칩 프로파일(TL2300, TL2500 등) 전환 및 사용자 커스텀 프리셋 저장이 정상 동작하는가?
- [ ] 비정상 입력(잘못된 Hex 문자열, 음수 크기 등) 시 안전하게 방어되는가?

## 6. Browser QA (실제 브라우저 렌더링 검증)
- [ ] Chrome DevTools 또는 실제 브라우저에서 화면을 직접 로딩하여 검증했는가?
- [ ] 메모리 바 줌/스크롤, 드래그 리사이징, 탭 전환이 부드러운가?
- [ ] 브라우저 콘솔창에 Uncaught Exception, React Key warning 등 오류가 0건인가?

## 7. Visual & UI/UX QA (시각적 완성도 검증)
- [ ] 반도체 엔지니어링 도구에 최적화된 고밀도 뷰 및 테마 일관성을 확보했는가?
- [ ] Hex 주소의 고정폭 폰트 정렬 및 WCAG AA 4.5:1 이상 가독성을 확보했는가?
- [ ] 주소 충돌 발생 시 붉은색 경고가 시각적으로 즉각 강조되는가?
- [ ] UI Reviewer 심사 점수 85점 이상을 획득했는가?

## 8. Regression Verification (기존 기능 무결성)
- [ ] 신규 기능 작업으로 인해 기존 템플릿, C 헤더 생성기, 바이너리 파서가 손상되지 않았는가?
- [ ] 기존 저장된 칩 프로파일 데이터가 안전하게 유지되는가?

## 9. Final Review & Diff Inspection (최종 검토)
- [ ] `git diff`를 검토하여 의도치 않은 파일 수정이나 불필요한 줄바꿈 변경이 없는지 확인했는가?
- [ ] 위 모든 게이트를 통과하기 전에는 절대로 "완료"라고 선언하지 않는다.
